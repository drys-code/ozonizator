# ozonizator

Мониторинг цены на кофе **Lavazza Qualita Oro, в зёрнах, 250 г** на Ozon.
Каждые 4 часа проверяет цену и присылает её в Telegram вместе со ссылкой на товар.

Товар: <https://www.ozon.ru/product/kofe-v-zernah-lavazza-qualita-oro-250-g-32933704/>

---

## Важно: почему это не работает на GitHub Actions

Изначальная задумка была — запускать проверку каждые 4 часа в GitHub Actions.
**Так сделать нельзя, и это не ошибка кода.**

Ozon блокирует запросы с зарубежных, «VPN-ных» и датацентровых IP-адресов.
Это подтверждено экспериментально: временный workflow был запущен на
`ubuntu-latest`, и результат оказался однозначным.

| Проверка | Результат |
| --- | --- |
| IP раннера | `172.171.6.120`, Des Moines, **US** |
| `curl` страницы товара | `307` → бесконечный редирект (`?__rr=1`, `?__rr=5`), тело 164 байта |
| Реальный браузер (Playwright + Chromium) | `HTTP 403`, `<title>Похоже, нет соединения</title>` |
| Блок с ценой | не найден (`webPrice count: 0`) |

То есть дело не в заголовках и не в отсутствии браузера: **любой** запуск с
зарубежного IP получает страницу-заглушку. О поддержке это писала и пресса:
[OZON и Wildberries начали ограничивать доступ пользователям с VPN](https://hi-tech.mail.ru/news/145623-ozon-i-wildberries-nachali-ogranichivat-dostup-polzovatelyam-s-vpn/).

Побочный вывод: прежние запуски workflow, которые завершались «успешно», на
самом деле были **ложными срабатываниями** — скрипт считал страницу
«Похоже, нет соединения» нормальным результатом и присылал в Telegram цену
«не определена». Именно это видно в `logs/ozon_checks.txt`.

Кроме того, прокси с российским **датацентровым** IP (VPS) тоже не поможет:
Ozon режет датацентры, а не только зарубежные адреса. Нужен обычный
российский «домашний» IP.

## Как сделано здесь

Проверка запускается **на вашем компьютере** по расписанию Windows: с вашего
российского домашнего IP Ozon отдаёт страницу нормально (проверено — цена
читается). Telegram-сообщение отправляет тот же скрипт.

```
Windows Task Scheduler (каждые 4 часа)
        │
        ▼
run_monitor.cmd ──► ozon_monitor.py
                       │  Playwright + Chromium
                       ▼
                  www.ozon.ru (ваш IP)  ──►  цена
                       │
                       ▼
                  Telegram Bot API  ──►  сообщение со ссылкой
```

### Файлы

| Файл | Назначение |
| --- | --- |
| `ozon_monitor.py` | Проверяет цену и отправляет сообщение в Telegram |
| `run_monitor.cmd` | Запускает проверку, пишет вывод в `logs\run.log` |
| `requirements.txt` | Зависимости Python |
| `logs\ozon_checks.txt` | История проверок |
| `logs\last_price.txt` | Предыдущая цена (для строки «изменение») |

## Установка

Уже настроено на этом компьютере. Если нужно повторить с нуля:

```powershell
py -m pip install -r requirements.txt
py -m playwright install chromium
```

### Секреты Telegram

Секреты **не** хранятся в репозитории. Скрипт читает их из файла
`%USERPROFILE%\.ozonizator\secrets.env`:

```
TELEGRAM_BOT_TOKEN=123456:AA...
TELEGRAM_CHAT_ID=123456789
```

Либо из переменных окружения с теми же именами (они имеют приоритет).

### Задача в планировщике

Создана задача `OzonCoffeePrice`, запуск каждые 4 часа:

```powershell
schtasks /Query /TN "OzonCoffeePrice" /V /FO LIST
```

Проверить вручную:

```powershell
schtasks /Run /TN "OzonCoffeePrice"
```

Удалить:

```powershell
schtasks /Delete /TN "OzonCoffeePrice" /F
```

### Ручной запуск

```powershell
.\run_monitor.cmd
```

Посмотреть браузер во время проверки:

```powershell
$env:OZON_HEADLESS="0"; py ozon_monitor.py
```

## Настройки

| Переменная | По умолчанию | Значение |
| --- | --- | --- |
| `TELEGRAM_BOT_TOKEN` | — | Токен бота (обязательно) |
| `TELEGRAM_CHAT_ID` | — | ID чата (обязательно) |
| `OZON_CITY` | `Владивосток` | Город доставки |
| `OZON_HEADLESS` | `1` | `0` — показать окно браузера |

Товар задаётся константами `PRODUCT_URL` и `PRODUCT_NAME` в `ozon_monitor.py`.

## О городе доставки

Ozon определяет город по IP-адресу и меняет его только через
интерактивный выбор адреса (геолокация в браузере на это не влияет).
На боевой странице товара остаётся тот город, который Ozon определил
по IP; он указывается в сообщении как «Город доставки».

На цену это не влияет: у одного и того же продавца и артикула цена
на Ozon единая по стране, а от города зависят срок и стоимость доставки.
Поэтому сравнение цен во времени остаётся корректным.

Если хочется видеть в сообщении именно «Владивосток» — переключите город
один раз в браузере на `ozon.ru` под тем же профилем; скрипт подхватит
сохранённый выбор.

## Что с GitHub Actions

Файл `.github/workflows/ozon-price.yml` оставлен, но **расписание отключено**,
чтобы он больше не присылал ложные сообщения. Workflow можно запускать
вручную (`workflow_dispatch`) для отладки.

Он заработает автоматически, если добавить в него российский IP —
например, self-hosted runner на домашнем компьютере
(`runs-on: self-hosted` вместо `ubuntu-latest`).
