# ozonizator

Мониторинг цены на кофе **Lavazza Qualita Oro, в зёрнах, 250 г** на Ozon.
Каждые 4 часа проверяет цену и присылает её в Telegram вместе со ссылкой на товар.

Товар: <https://www.ozon.ru/product/kofe-v-zernah-lavazza-qualita-oro-250-g-32933704/>

---

## Важно: почему это не работает на GitHub Actions

Изначальная задумка была — запускать проверку каждые 4 часа в GitHub Actions.
**Так сделать нельзя, и это не ошибка кода.**

Ozon блокирует запросы с зарубежных, «VPN-ных» и датацентровых IP-адресов.
Это подтверждено экспериментально: временный workflow был запущен на
`ubuntu-latest`, и результат оказался однозначным.

| Проверка | Результат |
| --- | --- |
| IP раннера | `172.171.6.120`, Des Moines, **US** |
| `curl` страницы товара | `307` → бесконечный редирект (`?__rr=1`, `?__rr=5`), тело 164 байта |
| Реальный браузер (Playwright + Chromium) | `HTTP 403`, `<title>Похоже, нет соединения</title>` |
| Блок с ценой | не найден (`webPrice count: 0`) |

То есть дело не в заголовках и не в отсутствии браузера: **любой** запуск с
зарубежного IP получает страницу-заглушку. О поддержке это писала и пресса:
[OZON и Wildberries начали ограничивать доступ пользователям с VPN](https://hi-tech.mail.ru/news/145623-ozon-i-wildberries-nachali-ogranichivat-dostup-polzovatelyam-s-vpn/).

Побочный вывод: прежние запуски workflow, которые завершались «успешно», на
самом деле были **ложными срабатываниями** — скрипт считал страницу
«Похоже, нет соединения» нормальным результатом и присылал в Telegram цену
«не определена». Именно это видно в `logs/ozon_checks.txt`.

Кроме того, прокси с российским **датацентровым** IP (VPS) тоже не поможет:
Ozon режет датацентры, а не только зарубежные адреса. Нужен обычный
российский «домашний» IP.

## Как сделано здесь

Проверка запускается **на вашем компьютере** по расписанию Windows: с вашего
российского домашнего IP Ozon отдаёт страницу нормально (проверено — цена
читается). Само сообщение отправляет GitHub Actions, поэтому **токен бота
остаётся в секретах репозитория и на компьютер не попадает**.

```
Windows Task Scheduler (каждые 4 часа)
        │
        ▼
run_monitor.cmd ──► ozon_monitor.py
                       │  Playwright + Chromium
                       ▼
                  www.ozon.ru (ваш IP)  ──►  цена
                       │  workflow_dispatch (цена передаётся параметром)
                       ▼
              GitHub Actions (ubuntu-latest)
                       │  секреты репозитория
                       ▼
                  Telegram Bot API  ──►  сообщение со ссылкой
```

Почему цену читает компьютер, а не раннер: у раннера зарубежный IP, Ozon
отдаёт ему заглушку. Зато у раннера есть секреты — он и отправляет сообщение.

### Файлы

| Файл | Назначение |
| --- | --- |
| `ozon_monitor.py` | Читает цену и запускает отправку сообщения |
| `run_monitor.cmd` | Запускает проверку, пишет вывод в `logs\run.log` |
| `.github/workflows/ozon-price.yml` | Отправляет сообщение в Telegram через секреты репозитория |
| `setup_telegram.py` | Настройка секретов для варианта «отправлять напрямую» |
| `test_telegram_message.py` | Самопроверка текстов сообщений (без реального чата) |
| `requirements.txt` | Зависимости Python |
| `logs\ozon_checks.txt` | История проверок |
| `logs\last_price.txt` | Предыдущая цена (для строки «изменение») |

## Установка

Уже настроено на этом компьютере. Если нужно повторить с нуля:

```powershell
py -m pip install -r requirements.txt
py -m playwright install chromium
```

Отправка через GitHub включается переменной `OZON_TELEGRAM_VIA_GITHUB=1`
(она уже задана в `run_monitor.cmd`). Токен для запуска workflow берётся из
переменной `GITHUB_TOKEN`/`GH_TOKEN` либо из Git Credential Manager — тот же,
которым вы делаете `git push`. Нужны права `repo` и `workflow`.

Проверить связку с Telegram, не дожидаясь расписания:

```powershell
gh workflow run ozon-price.yml          # только проверка: бот и chat id рабочие
```

### Секреты Telegram

По умолчанию токен **не нужен на компьютере** — сообщения отправляет GitHub
Actions из секретов репозитория.

Если захотите отправлять напрямую с компьютера (без GitHub), запустите
одну команду — токен вводится скрытно и сразу проверяется:

```powershell
py setup_telegram.py
```

Скрипт сохранит их в `%USERPROFILE%\.ozonizator\secrets.env` (вне репозитория):

```
TELEGRAM_BOT_TOKEN=123456:AA...
TELEGRAM_CHAT_ID=123456789
```

Либо задайте переменные окружения с теми же именами (они имеют приоритет).

### Задача в планировщике

Создана задача `OzonCoffeePrice`, запуск каждые 4 часа:

```powershell
Get-ScheduledTask -TaskName "OzonCoffeePrice"
Get-ScheduledTaskInfo -TaskName "OzonCoffeePrice"
```

Задача настроена с `AllowStartIfOnBatteries`, иначе Windows молча пропускает
запуск на ноутбуке, работающем от батареи.

Проверить вручную:

```powershell
Start-ScheduledTask -TaskName "OzonCoffeePrice"
```

Удалить:

```powershell
Unregister-ScheduledTask -TaskName "OzonCoffeePrice" -Confirm:$false
```

### Ручной запуск

```powershell
.\run_monitor.cmd
```

Посмотреть браузер во время проверки:

```powershell
$env:OZON_HEADLESS="0"; py ozon_monitor.py
```

### Самопроверка

```powershell
py test_telegram_message.py
```

Проверяет текст сообщений и отправку через локальную заглушку Telegram,
не трогая реальный чат.

## Настройки

| Переменная | По умолчанию | Значение |
| --- | --- | --- |
| `OZON_TELEGRAM_VIA_GITHUB` | `1` в `run_monitor.cmd` | `1` — отправлять через GitHub Actions (токен не нужен локально) |
| `TELEGRAM_BOT_TOKEN` | — | Токен бота (только для прямой отправки) |
| `TELEGRAM_CHAT_ID` | — | ID чата (только для прямой отправки) |
| `GITHUB_TOKEN` / `GH_TOKEN` | из Git Credential Manager | Токен с правами `repo` и `workflow` |
| `OZON_CITY` | `Владивосток` | Город доставки |
| `OZON_HEADLESS` | `1` | `0` — показать окно браузера |

Товар задаётся константами `PRODUCT_URL` и `PRODUCT_NAME` в `ozon_monitor.py`.

## Устойчивость к антибот-защите

Ozon периодически отвечает страницей `Antibot Challenge Page` вместо карточки
товара. Скрипт делает до 3 попыток с увеличивающейся паузой (25 и 50 секунд),
поэтому одиночный вызов-заглушка не превращается в ложное сообщение об ошибке.
Если все попытки не удались, приходит честное сообщение о причине.

## О городе доставки

Ozon определяет город по IP-адресу и меняет его только через
интерактивный выбор адреса (геолокация в браузере на это не влияет).
На боевой странице товара остаётся тот город, который Ozon определил
по IP; он указывается в сообщении как «Город доставки».

На цену это не влияет: у одного и того же продавца и артикула цена
на Ozon единая по стране, а от города зависят срок и стоимость доставки.
Поэтому сравнение цен во времени остаётся корректным.

Если хочется видеть в сообщении именно «Владивосток» — переключите город
один раз в браузере на `ozon.ru` под тем же профилем; скрипт подхватит
сохранённый выбор.

## Что умеет GitHub Actions в этой схеме

| Что | Результат |
| --- | --- |
| Читать цену с Ozon | ❌ невозможно (зарубежный IP раннера) |
| Отправлять сообщение в Telegram | ✅ работает, проверено (`HTTP 200`) |

Поэтому расписание живёт в планировщике Windows, а GitHub Actions
используется как «отправляющий»: он выполняет `workflow_dispatch`
с ценой и отправляет её в Telegram, используя секреты репозитория.
Токен бота при этом не нужно хранить на компьютере.

Ручной запуск workflow без параметров — это проверка связи с ботом.

Если в будущем появится российский сервер или self-hosted runner,
достаточно заменить `runs-on: ubuntu-latest` на `runs-on: self-hosted`
и вернуть `schedule`, чтобы убрать зависимость от включённого компьютера.
